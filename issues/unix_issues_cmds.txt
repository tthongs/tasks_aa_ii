UNIX COMMANDS MASTER LOG: REPOSITORY ISSUES & SYSTEM MAINTENANCE

This file documents all Unix shell commands used across the resolution of 
issues recorded in the issues/ directory. Commands are segregated by technical 
domain, explaining context, rationale, and breaking down flags for easy 
understanding.

1. SYSTEM DIAGNOSTICS & HARDWARE INSPECTION
===============================================================================

-------------------------------------------------------------------------------
1.1 uname - Kernel Information
-------------------------------------------------------------------------------
Command:
  uname -a

Context & Purpose:
  Used in ISSUE_011 / REPORT_003 to identify the operating system, hostname, 
  kernel release version, and machine architecture before performing hardware 
  driver checks.

Command Breakdown:
  -a : Print all system information (kernel name, nodename, release, version, 
       machine, processor, hardware platform, and OS).

-------------------------------------------------------------------------------
1.2 lspci - PCI Bus & Hardware Device Inspection
-------------------------------------------------------------------------------
Command:
  lspci -nnk | grep -A 3 -i audio

Context & Purpose:
  Used to identify all PCI audio hardware, vendor/device IDs, and currently 
  loaded kernel drivers (e.g., Intel Raptor Lake cAVS and NVIDIA GPU Audio).

Command Breakdown:
  lspci     : List all PCI devices connected to the motherboard.
  -nn       : Display both vendor/device names and hexadecimal IDs [8086:51ca].
  -k        : Show kernel drivers handling each device and kernel modules.
  grep -A 3 : Search for "audio" (case-insensitive) and print 3 lines after match.

-------------------------------------------------------------------------------
1.3 lsusb & lsblk & blkid - USB, Block Devices, and UUID Identification
-------------------------------------------------------------------------------
Commands:
  lsusb
  lsblk -f
  blkid /dev/sda1

Context & Purpose:
  Used in ISSUE_007 (SSD Mount) and ISSUE_011 (Hardware Audit) to discover USB 
  peripherals and locate drive UUIDs for stable mount point configurations.

Command Breakdown:
  lsusb    : List USB buses and attached devices (e.g., RTL9210 NVMe Enclosure).
  lsblk -f : List block devices in a tree structure with filesystem types and UUIDs.
  blkid    : Print block device attributes (UUID, LABEL, TYPE) for fstab entries.

-------------------------------------------------------------------------------
1.4 journalctl & dmesg - System Log & Kernel Buffer Inspection
-------------------------------------------------------------------------------
Commands:
  journalctl -b -k | grep -iE 'sof|dmic|audio|hda'
  journalctl -p 3 -b 0 --no-pager
  journalctl --vacuum-time=2d

Context & Purpose:
  Used across ISSUE_003 (Boot Bottlenecks), ISSUE_007 (SSD disconnects), and 
  ISSUE_009 (Bluetooth Firmware) to inspect system errors and clean up log bloat.

Command Breakdown:
  -b / -b 0  : Filter logs to current boot session.
  -k         : Filter to kernel log messages only (dmesg equivalent).
  -p 3       : Filter by priority level 3 (ERRORS) up to 0 (EMERGENCY).
  --no-pager : Output directly to terminal without piping to less/cat.
  --vacuum-time=2d : Delete journal log files older than 2 days to free disk space.

-------------------------------------------------------------------------------

  chmod +x                : Marks script executable so `grub-mkconfig` processes it.
  halt                    : Built-in GRUB shell command that powers off hardware immediately.

  journalctl -b -3 -k   : Inspects kernel ring buffer logs for the specific failed boot.
  grep -iE "..."        : Isolates blocked task call stacks, semaphore ownership, and udev worker terminations.

  locale -a            : Lists available compiled locales to verify en_IN.utf8 availability.

SECTION 15: KERNEL MODULE BOOT STALL & SERVICE TIMEOUT RESOLUTION
===============================================================================

-------------------------------------------------------------------------------
15.1 Masking Redundant Early Userspace Module Loads
-------------------------------------------------------------------------------
Commands:
  sudo ln -sf /dev/null /etc/modules-load.d/nvidia-utils.conf

Context & Purpose:
  Masks the distribution-shipped `/usr/lib/modules-load.d/nvidia-utils.conf` file.
  Prevents `systemd-modules-load.service` from attempting to parallel-load `nvidia-uvm`
  at early boot while `systemd-udevd` and ACPI NVPCF handlers are initializing GPU DRM,
  eliminating the rw-semaphore lock contention race condition.

Command Breakdown:
  ln -sf /dev/null ... : Creates a masking symlink in /etc overriding /usr/lib configuration.

-------------------------------------------------------------------------------
15.2 Systemd Modules Load Timeout Clamp Drop-In
-------------------------------------------------------------------------------
Commands:
  sudo mkdir -p /etc/systemd/system/systemd-modules-load.service.d
  sudo tee /etc/systemd/system/systemd-modules-load.service.d/10-timeout.conf << 'EOF'
  [Service]
  TimeoutStartSec=10s
  EOF
  sudo systemctl daemon-reload

Context & Purpose:
  Overrides systemd's default 90-second service timeout for `systemd-modules-load.service`.
  Ensures that if any individual kernel module probe stalls, the service aborts after
  10 seconds instead of blocking the entire bootloader and userspace startup for 1.5 minutes.

Command Breakdown:
  mkdir -p ...           : Creates systemd service drop-in configuration directory.
  tee ...                : Writes TimeoutStartSec=10s unit override.
  systemctl daemon-reload: Signals systemd manager to reload unit files and apply new limits.

-------------------------------------------------------------------------------
15.3 Deterministic Early KMS & Modprobe Parameter Provisioning
-------------------------------------------------------------------------------
Commands:
  sudo mkdir -p /etc/mkinitcpio.conf.d
  sudo tee /etc/mkinitcpio.conf.d/10-nvidia.conf << 'EOF'
  MODULES+=(nvidia nvidia_modeset nvidia_uvm nvidia_drm)
  EOF
  sudo tee /etc/modprobe.d/nvidia.conf << 'EOF'
  options nvidia NVreg_InitializeSystemMemoryAllocations=0 NVreg_DynamicPowerManagement=0x02
  options nvidia-drm modeset=1 fbdev=1
  blacklist nouveau
  blacklist nova_core
  blacklist nova_drm
  EOF
  sudo mkinitcpio -P

Context & Purpose:
  Configures deterministic sequential kernel mode setting (KMS) driver inclusion
  in early initramfs images, setting optimal runtime dynamic power management (RTD3)
  and framebuffer device integration before userspace graphical targets start.

Command Breakdown:
  MODULES+=(...) : Appends NVIDIA driver modules to early initramfs image module list.
  modeset=1      : Enables Direct Rendering Manager (DRM) kernel mode setting.
  fbdev=1        : Enables generic DRM framebuffer emulation device (/dev/fb0).
  mkinitcpio -P  : Recompiles initramfs images for all installed kernel presets.
